# Ротация секретов: BETTER_AUTH_SECRET и APP_ENCRYPTION_KEY

## Почему два ключа

До 3.4.86 все секреты интеграций (шлюзы, SMTP, Telegram, OAuth, 2FA)
шифровались как `enc:v1:` ключом, выведенным из `BETTER_AUTH_SECRET`.
Ротация этого секрета одновременно убивала сессии **и** все сохранённые
секреты — после смены надо было вручную вписывать все ключи заново.

С 3.4.86 есть отдельный ключ `APP_ENCRYPTION_KEY`: новые секреты пишутся
как `enc:v2:` и не зависят от `BETTER_AUTH_SECRET`. Старые `enc:v1:`
продолжают читаться как раньше.

## Первичная настройка (один раз)

На VPS, в папке проекта (рядом с `docker-compose.yml` и `.env`):

```bash
openssl rand -base64 32
```

1. Добавьте в `.env`:
   ```
   APP_ENCRYPTION_KEY=<вывод команды>
   ```
2. Добавьте в `docker-compose.yml`, в `app:` → `environment:`
   (рядом с `BETTER_AUTH_SECRET`):
   ```yaml
   APP_ENCRYPTION_KEY: ${APP_ENCRYPTION_KEY:-}
   ```
   С 3.4.86 эта строка уже есть в репозитории — для свежих установок.
   На существующем VPS её надо добавить руками: автообновление меняет
   только образ, не compose-файл.
3. Пересоздайте контейнер приложения:
   ```bash
   docker compose up -d app
   ```

Без этого ключа код просто продолжает шифровать как `enc:v1` и пишет
одно предупреждение в лог при первом сохранении секрета. Ничего не ломается.

## Перешифровка хранимых секретов v1 → v2

Выполнять ПОСЛЕ того, как ключ задан и задеплоен код 3.4.86+:

```bash
docker compose exec app node scripts/encrypt-secrets.mjs --to-v2 --dry-run
docker compose exec app node scripts/encrypt-secrets.mjs --to-v2
```

Скрипт расшифровывает `enc:v1:` значения ключом `BETTER_AUTH_SECRET` и
перешифровывает их как `enc:v2:` ключом `APP_ENCRYPTION_KEY`. Plaintext
значения шифруются сразу в v2, уже-v2 пропускаются. Идемпотентен:
повторный запуск покажет `0 row(s) updated` — это и есть проверка, что
перешифровка завершена.

## Ротация BETTER_AUTH_SECRET (только после перешифровки!)

1. Убедитесь, что повторный `--to-v2 --dry-run` показывает 0 изменений.
2. Задайте новое значение `BETTER_AUTH_SECRET` в `.env`.
3. `docker compose up -d app`.
4. Все сессии сгорят — это ожидаемо, все заново логинятся.
5. Секреты интеграций (`enc:v2:`) продолжат работать.

## Чего нельзя делать

- **Не удаляйте `APP_ENCRYPTION_KEY`, пока в базе есть значения `enc:v2:`**
  — чтение таких секретов падает с понятной ошибкой, и интеграции
  (оплата, почта, Telegram) перестают работать.
- Не ротируйте `BETTER_AUTH_SECRET` до перешифровки: все оставшиеся
  `enc:v1:` значения станут нечитаемыми.
- Ротация самого `APP_ENCRYPTION_KEY` отдельным скриптом пока не
  поддерживается: для неё нужен старый и новый ключ одновременно.
  Если понадобится — делается как отдельный режим скрипта.
